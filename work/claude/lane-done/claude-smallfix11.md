# smallfix11 - THE HORNET'S NEST played the synth for ~a minute (Daniel 11-03)
Root cause: src/audio.js loadTrack() aborted a music fetch after 20 s TOTAL (MUSIC_RETRY.timeoutMs). hornetnest.ogg is 2.1 MB (the biggest level track), so on a slow/cold line it was cut at 20 s and restarted from zero, 3 times (~60 s), then trackFailed=true let schedule() play the generic synth until a later retry landed. Level->track mapping (hornets-nest.js music:'hornetnest', TRACKS key) and the map preload were correct; the SFX lane already holds while a track is pending.
Fix (one path for every file track): (1) the timeout is now a STALL timeout (re-armed on each received chunk, body streamed); (2) trackFailed (the only thing that lets the synth stand in) is set only after the whole retry budget (10 rounds x 3 tries), not after the first 3. The existing guard in schedule() then keeps a file track silent (plus level ambience) until it decodes, and playFile starts it the moment it lands. Synth remains for file-less tracks and exhausted retries.
Verified: new tools/music-slowfile.mjs (450 kbit/s, cold, TRACK=hornetnest): new code plays at 49.9 s with 0 synth-would-play polls; the same test on claude/batch140 FAILS. tools/music-priority.mjs (frogking, 1600 kbit/s) ok; tools/music-levelstart.mjs ok. Full suite not run.
Other tracks: all TRACKS entries share loadTrack, so every file track/boss gets this; biggest files benefit most.
Not done / recs: no extra preload added (map-node preload after 350 ms rest and boss preload 100 tiles out already exist). A fade-in on landing is the existing track fade. Question: none.
