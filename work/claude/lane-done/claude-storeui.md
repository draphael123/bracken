# claude/storeui - settings in tabs, rebinding, the co-op guide, the ability audit

Branch claude/storeui (off claude/batch48 5b0ec84). Sonnet lane. The store redesign and the live ability previews (item 17a) were not part of tonight.

## What changed

1. SETTINGS IN TABS (item 18). Settings is five tabs: AUDIO, DISPLAY, GAMEPLAY, CONTROLS, ACCESSIBILITY, on a strip along the top (`src/settings-ui.js` holds the tab -> row lists, names only).
   - Every old row is on exactly one tab under its old name, and no SET key or saved value moved: the rows still run through the same menuAdjust/menuConfirm, so nothing about a save changed. The COMBAT classic/weighty switch is on GAMEPLAY and works as before.
   - AUDIO: sound test, music, the four volumes, sound FX, voices. DISPLAY (with sub-headers PICTURE / LOOK / WORLD / EFFECTS): full screen, pixel scale, camera, brightness, filter, scanlines, grain, vignette, UI colour (theme), font, text colour, HUD, foe health, hit numbers, timer, tenths, FPS, ground light, air, parallax, arena tint, weather, ambient life, look down, screen shake, particles, impact FX, boss intro. GAMEPLAY: difficulty, combat, game speed, hit stop, Iron Knight, the helpers (jump assist, way-on arrow, text speed), then SAVE (export/import/erase) and TESTING (god mode, invincible, hitboxes). CONTROLS: the card, Rebind keys, block hold/toggle, Swap Z/X, rumble, Co-op guide, Reset controls. ACCESSIBILITY: big text, colour tells, Reduce motion, flashes, foe outline.
   - Navigation: the strip is the first selectable row (up from the first row; LEFT/RIGHT change tab). TAB or E = next tab, Q = previous, LB / RB on a pad. UP/DOWN/LEFT/RIGHT and A always drive the menus even if the play keys were rebound.
   - The Settings panel is wider (272 px) than the pause menu so five labels fit at 6 px; the strip and rows were measured with textfit at 320x180.
2. REBINDING (item 22a). `src/controls.js` (pure model + the rebind screen's draw/update). Settings > CONTROLS > Rebind keys: three pages (KEYBOARD P1, GAMEPAD P1, GAMEPAD P2; LB/RB, TAB or the strip switch page), 15 actions: move left/right, up/look up, crouch/down, jump, attack (hold = heavy: one key, as the game has always had it), C (guard or the hero's ability), dodge, skill one (F), skill two (G), talk, map, skills menu (Q), pause, emote. Two slots per action (Z/ENTER listens, BACKSPACE clears, ESC cancels), a key or button used by two actions is flagged red on both rows with the name of the other, R and M are refused (reserved), "reset this page" asks twice, Reset controls on the tab resets all three pages. Untouched actions keep every default key (alternates included), so an old save behaves exactly as before. Stored in `bracken.settings` as `binds` (cleaned on load: only known actions, real keys, buttons 0-31). ESC, START, the arrows and A/Z/ENTER/SPACE always work the menus, so a bad rebind cannot lock anyone out. Pad polling reads a table per pad (`padStateOf`), so co-op player two's pad has its own bindings.
3. THE CARD (item 18/22a). The controls card is now built by `cardRows()` in controls.js from the chosen keys and the hero's own words; the per-hero tables that lived in main.js (DK_KEYS/WARDEN_KEYS `controls`, GEO_KEYS) are removed. Every hero gets a CROUCH row (HOLD DOWN, STILL); the Pyromancer's is EMBER WARD (HOLD DOWN, STILL) and her C row is now "EMBER / JET: TAP C EMBER, HOLD JET" (it was wrongly "block"). Paladin C = mend / aegis, Freebooter C = parry / hook, the others as before. The two "skill three/four" rows were removed (the game has two slots). Card is opened from Settings or the title's CONTROLS; Z on the card opens the rebind page; ESC now returns to where it was opened from (from the title it used to land on a stale menu).
4. CO-OP TAUGHT (item 22b). `src/coop-help.js`: a four-page HOW TO PLAY (JOINING; THE SECOND PLAYER: pad defaults + where to rebind; ONE SCREEN, DOWN NOT DEAD; SHARED, AND NOT). The rules use the game's own DOWN_T / REVIVE_T. It opens by itself the first time co-op is switched on (`SET.coopHelpSeen`, kept with the settings, once), and from the pause menu row "Co-op guide" and the CONTROLS tab. In-game: the first two downs of a save show "DOWN, NOT DEAD: YOUR PARTNER STANDS ON YOU..." and the first two revives show "UP AGAIN AT A THIRD OF YOUR HEALTH..." (`PROG.coopTips`, saved with the slot).
5. ABILITY AUDIT (item 17b). `docs/ability-audit.md`, read-only, no code: all 196 catalog skills of the 7 heroes, verdict per skill, cross-hero duplicates, and a ranked list of 23 proposed changes. Headline: behaviour is clean (nothing unread, no borrowed mechanics), the problems are passive icons (7 of 10 Geomancer passives wear a sword, RUMBLE wears a coin), eight actives wearing another skill's icon, wrong descriptions (Holy Charge says shield-first; the Freebooter card has the C taps backwards), no actives after level 8 for four heroes, and shared templates. The audit was produced by a read-only sub-agent and spot-read by me; it was not re-verified line by line.
